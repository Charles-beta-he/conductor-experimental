# UNKNOWN-resolution successor protocol v2 — design R1

Status: design candidate, not implemented or accepted. Canonical overall requirements remain ../SPEC.md; this addendum is version-isolated and does not amend frozen M2/M3/M4 bytes.

## Objective model / Spec Brief

Goal: real failed execution -> durable UNKNOWN -> separately approved, evidence-bound resolution to FAILED -> fresh full-history M5 adoption -> distinctly granted repaired execution -> independently verified artifact. Preserve raw UNKNOWN events, spent starts, task/attempt identity, and separation of execution / resolution / plan approval / ACP completion authority.
Non-goals: v1 database migration, clearing arbitrary orphan processes, remote authentication, malicious same-UID containment, external effects rollback, automatic retry, live Hermes activation, model calls, release/deploy/push. Scope: trusted synchronous local POSIX host and operator-selected programs that do not escape the owned process group. Detached descendants and noncooperating writers are outside the model.
Facts: frozen runtime/store.py converts execution and verification errors to UNKNOWN and has no resolution API. replanning Journal.adopt refuses any historical UNKNOWN/RUNNING. Existing process adapter kills the newly owned group and reaps its direct child, but its plain exception does not separately attest whether cleanup succeeded. Existing v1 stores cannot be safely reinterpreted or used as v2 evidence.
Paths: mutate frozen M2 (rejected: breaks evidence identity); sidecar FAILED projection over v1 (rejected: original slot remains held, risks counterfeit owner); new v2 attempt owner on a new private root (chosen: explicit opt-in schema and module identity, v1 stays unchanged). No migration or second store per revision. Reversibility: stop using new root; no live install/config change.

## Version / API / ownership

New package acp-conductor-resolution-experiment 0.0.2; module acp_conductor_resolution. Reuse only public immutable Request/Grant contracts from frozen acp_conductor_runtime. Fork own Store implementation with explicit provenance into the new package, not a subclass reaching v1 private setters. Root contains attempts-v2.sqlite3 and protocol marker in DB config; reject any root with attempts.sqlite3 before writing v2 state. No automatic migration. M3 Flow and M4 remain unmodified and remain v1-only: the frozen Flow checks exact Store type and MUST reject v2 Store. No compatibility claim, monkeypatch or type masquerade is permitted. The version-isolated v2 host explicitly orchestrates public v2 Store and frozen planner/Journal APIs rather than calling frozen Flow or M4. Initial resolution acceptance directly exercises that host sequence; a reusable host wrapper and its full-history admission/pre-execution gates are required for M5 host acceptance, not implied by this successor. The trusted host reads every journal binding (including retired tasks) from this same Store before adoption and execution; unknown/missing/mismatched history stops it, and submit/bind interruption stops for explicit readback rather than inventing bindings. Root/caps cannot change across revisions or reopen.
Public: Request, Grant, Store.submit/query/run/verify/artifact/reconcile/cancel; SubprocessAdapter(identity, execute_authorized); ResolutionGrant(attempt_id, request_digest, evidence_digest, expires_at); Store.resolution_evidence(attempt_id), Store.resolve(attempt_id, grant), Store.history(attempt_id), Store.stats(). No arbitrary public state setter. Resolution outcome is only FAILED, never VERIFIED. No resolution for PREPARED/RUNNING/CANDIDATE/VERIFIED/CANCELLED. Exact replay of an already committed resolution only returns immutable historical FAILED readback; changed identity/evidence conflicts reject. Replay is not new authority. Its identity is the exact original grant tuple including expires_at; a matching committed tuple may be read back after wall-clock expiry, but a different expiry is a conflicting grant, not a replay.

## Evidence and execution fencing

1. Durable PREPARED->RUNNING claim increments cumulative starts once and records unique call token. All updates from runner bind attempt and token and require RUNNING. No lease stealing, no repeat call. UNKNOWN/RUNNING retain slot; only successful explicit resolution releases UNKNOWN slot, never refunds starts.
2. New bounded process adapter executes explicit argv in a new POSIX session with bounded stdin/stdout/stderr, timeout, pinned files and final Grant check. It returns a typed ExecutionResult only AFTER owned group termination and direct-child reap complete. After SIGKILL of the invocation-owned group and direct-child wait, it checks killpg(group, 0) until ESRCH, bounded to one second; inability to establish group absence means no closure attestation. This is conservative for unreaped descendant zombies too. No detached-child support is claimed. Result contains bounded bytes on success or sanitized exception class on failure and a quiescent flag. Cleanup failure or interruption raises rather than attests closed. Trusted adapters may implement this port; model outputs never select adapters or issue results. This is a local trusted code contract, not cryptographic proof or a sandbox. No stored PID is ever killed after restart.
3. Runner durably records execution_closed with the matching token only after receiving a valid quiescent result, including when a concurrent cancellation/reconcile already changed RUNNING to UNKNOWN. This late closure can add evidence but never publish a late artifact or promote UNKNOWN. Failure before receiving a valid closure, crash after claim, cleanup failure or SIGKILL remains unresolved UNKNOWN: no resolution evidence is available. Existence of artifact/PID/elapsed time is not closure proof.
4. Late results are fenced by state+token for CANDIDATE/VERIFIED promotion. Reconciliation is never quiescence evidence. Failed verification after a closed execution records UNKNOWN; artifact readback corruption conservatively projects UNKNOWN. Before resolving a projected UNKNOWN, persist a fresh verify failure through the owner's public verify operation; resolve only stored UNKNOWN.
5. Resolution evidence is canonical JSON (sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False) including protocol=2, attempt_id, request_digest, adapter_id, call_token, closure record, and UNKNOWN event sequence. SHA256 of ASCII bytes is evidence_digest. Fresh readback from the same v2 DB is mandatory. UNKNOWN sequence prevents ABA/stale grant reuse. ResolutionGrant is a separate trusted-host authorization with finite strict numeric expiry checked at transaction use point. It is not an execution Grant or plan Approval.
6. resolve requires exact type/binding, current UNKNOWN, execution_closed, matching evidence and unexpired grant in one BEGIN IMMEDIATE transaction. Append resolution event (including binding) and FAILED event atomically; retain all preceding UNKNOWN and execution history. Resolution does not assert external effects were undone; operator accepts the failed attempt's recorded residual-effects boundary. No hidden callback/model/tool invocation.
7. Repeated run/reconcile/cancel never undo FAILED or consume another start. Duplicate/concurrent resolve idempotently reads one immutable resolution. Different grant/attempt/evidence must not release a slot. Same task identity cannot be rebound, including FAILED history. New task and separately granted execution required.

## Acceptance / negative cases / evidence

A. Real Python nonzero exit and expected-text mismatch both first persist UNKNOWN, cannot be adopted by M5, then resolve under explicit correct grant to FAILED, retain UNKNOWN history; new task is adopted, separately granted, executed and verified. Demonstration must use fresh processes for readback, not fabricated Observation(FAILED).
B. No grant, execution Grant substituted, wrong attempt/request/evidence, expired/bool/NaN expiry reject with unchanged events, slots, starts, zero new calls. Non-UNKNOWN or missing closure rejects. Resolution after SIGKILL of runner cannot proceed; reopened run does not replay. State changes/cancellation while adapter active must prevent premature resolution and late promotion.
C. starts stay cumulative after resolution and across reopen/revision; cap exhaustion starts zero adapters. max_running slot released only by committed resolution. One task/one attempt; idempotency conflict and old execution Grant remain denied. Competing starts/resolutions serialize.
D. Artifact corruption/missing remains non-verifiable, including retired history. Fresh projections inspect complete M5 bindings; unknown historical attempts never silently disappear.
E. Run all unchanged planner/runtime/composition/dataflow/replanning suites plus new resolution tests; compare frozen candidate inventories before/after. Build/install isolated wheels and exercise installed source, not only checkout.
F. Second concrete process runtime initially Node.js when available: same real success, nonzero, mismatch, timeout, explicit resolution, no-replay and budget contracts. Label Python/Node as language runtimes, NOT two independently integrated AI Agent runtimes. Original long-term second Agent runtime conformance remains outstanding unless a real supported Agent adapter is exercised under separate existing authority; no new model calls implied here.
